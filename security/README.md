# Безпека програм та даних — лабораторні роботи

| Робота | Тема | Варіант | Звіт |
|---|---|---|---|
| №6 | Аутентифікація користувачів на основі токенів безпеки | 2 — за хеш-образами | [lab_6/README.md](lab_6/README.md) |
| №7 | Підсистема керування доступом | 1 — довірче (дискреційне) керування | [lab_7/README.md](lab_7/README.md) |

**Перед здачею читати [info.md](info.md)** — усе найважливіше за 10 хвилин.

Обидві роботи — одна програма: сервер ЛР7 використовує модуль аутентифікації,
написаний для ЛР6, і ту саму базу реєстраційної інформації.

## Вимоги

Windows + Python 3 (перевірено на 3.13). Сторонні пакети **не потрібні**: уся
криптографія — це прямі виклики Microsoft CryptoAPI (`advapi32.dll`) через `ctypes`.
Для роботи з реальним токеном потрібен флеш-диск; без нього все працює з текою-замінником.

## Швидкий старт

```powershell
cd C:\uni_year_4\security\lab_6
.\demo.ps1                 # аутентифікація: 2 вдалі + 4 невдалі сценарії

cd ..\lab_7
.\demo.ps1                 # керування доступом: 3 суб'єкти, 12 об'єктів
```

Без флешки додайте `-TokenDir C:\temp\tok` до будь-якого з демо.
Протоколи роботи з'являються у `lab_6\logs\` та `lab_7\logs\`.

## Структура

```
security/
├── common/        спільні модулі обох робіт
│   ├── mscrypto.py   Microsoft CryptoAPI через ctypes: SHA-256, ГВЧ, AES-256
│   ├── token.py      пошук знімного диска, захищений файл токена
│   ├── netproto.py   TCP + шифрування трафіку
│   ├── userdb.py     база реєстраційної інформації
│   ├── authcore.py   ядро аутентифікації (ЛР6, використовує й ЛР7)
│   └── protolog.py   протоколювання
├── lab_6/         аутентифікація за токеном безпеки
├── lab_7/         підсистема керування доступом
└── vm/            прогін на двох машинах (хост + VirtualBox)
    ├── start_servers_host.ps1   піднімає обидва сервери на 0.0.0.0
    └── run_client.bat           клієнт, що запускається з флешки у VM
```

## Прогін на двох машинах

Деталі — у розділі 4В звіту [ЛР6](lab_6/README.md). Коротко: на флешці лежать
`python\` (Python embeddable), `security\` і `RUN_ON_VM.bat`, тож у віртуальну
машину нічого встановлювати не треба.

```powershell
.\vm\start_servers_host.ps1 -Enroll   # на хості
# далі у VM просто двічі клікнути RUN_ON_VM.bat на флешці
```

Адресу сервера скрипт сам записує на токен (`server_ip.txt`), тож у віртуальній
машині нічого вводити не треба.
