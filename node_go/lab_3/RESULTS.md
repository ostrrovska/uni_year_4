## Демонстрація скасування (`-cancel-after`)

```
go run . -tasks 2000 -workers 4 -buffer 10 -cancel-after 1ms

Custom run
┌───────┬─────────┬────────┬───────────┬──────────┬────────┬──────────┬──────────────────┐
│ Tasks │ Workers │ Buffer │ Completed │ Time, ms │ Jobs/s │      Sum │            Check │
├───────┼─────────┼────────┼───────────┼──────────┼────────┼──────────┼──────────────────┤
│  2000 │       4 │     10 │       302 │      1.1 │ 284262 │ 13757154 │ partial 302/2000 │
└───────┴─────────┴────────┴───────────┴──────────┴────────┴──────────┴──────────────────┘
```

Контекст скасовується через 1 мс, що встигає менше ніж за 2000 задач при
4 воркерах. `producer` і `worker` виходять через гілку `<-ctx.Done()` у
своїх `select`, pipeline завершується без deadlock і без паніки, а колонка
`Check` чесно показує часткове виконання (`302/2000`) замість того, щоб
мовчки вдавати повний прогін.

## Перевірка на гонки даних

На самій Windows-машині немає C-компілятора, а `-race` лінкує TSan-рантайм
через cgo, тому команда виконана в WSL (Ubuntu, де вже є `gcc`), проти того
самого коду на диску (`/mnt/c/...`):

```
$ go run -race . -tasks 2000 -workers 8 -buffer 10

Custom run
┌───────┬─────────┬────────┬───────────┬──────────┬────────┬────────────┬───────┐
│ Tasks │ Workers │ Buffer │ Completed │ Time, ms │ Jobs/s │        Sum │ Check │
├───────┼─────────┼────────┼───────────┼──────────┼────────┼────────────┼───────┤
│  2000 │       8 │     10 │      2000 │     10.3 │ 194999 │ 2698657000 │    ok │
└───────┴─────────┴────────┴───────────┴──────────┴────────┴────────────┴───────┘

[exited with code 0]
```

Жодного `WARNING: DATA RACE`, код виходу 0. Це підтверджує те, що
випливає з архітектури: кожен worker працює лише зі своєю копією `Job`,
отриманою з channel, не чіпаючи чужі дані, а єдиний, хто читає `results` і
накопичує статистику, — це `main`-goroutine, без додаткових
goroutine-читачів. На Windows з встановленим MinGW-w64 (`choco install
mingw`) та сама команда виконується прямо з `go-service`, без WSL.
